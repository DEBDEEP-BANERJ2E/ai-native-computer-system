## 1. The Principle of Unambiguous Address Terminology

In the AI-Native Computer System, the word **"address"** is never used loosely. Every memory reference is explicitly categorized into one of 15 formal address classifications:

```
Source Variable / Symbol Name
            │
            ▼
Section-Relative Offset (.text + 0x120)
            │
            ▼
Link-Time Virtual Address (Linker Script VA)
            │
            ▼
Executable Load Virtual Address (ELF PT_LOAD)
            │
            ▼
Process Virtual Address (Process VA space)
            │
            ▼
Capability Effective Address (c.base + c.offset + imm) ──► CapabilityLite Bounds/Tag/Perm Check
            │                                                      │ [Denied: Capability Fault]
            ▼                                                      ▼
Sv32 MMU Translation ([VPN1:10][VPN0:10][Offset:12]) ────► Page Table Walk / TLB
            │                                                      │ [Invalid/Forbidden: Page Fault]
            ▼                                                      ▼
34-Bit Physical Address (PPN[21:0] + Offset[11:0])
            │
      ┌─────┴─────┐
      ▼           ▼
 L1 I/D Cache    System MMIO (0x80000000..0x8000FFFF)
      │
  Unified L2
      │
 Physical RAM
      │
Secondary Storage Block / Swap LBA (Paging Tier)
```

## 2. Complete Address Hierarchy Reference Table

| Classification | Notation / Bit Format | Responsible Subsystem | Purpose / Invariants |
| :--- | :--- | :--- | :--- |
| **Symbol Address** | `_start`, `kernel_main` | Compiler / Assembler | Human-readable identifier for functions and variables. |
| **Section Offset** | `.text + 0x0040` | Assembler / Linker | Byte offset relative to the beginning of an ELF section. |
| **File Offset** | `elf_header.e_phoff` | Linker / Loader | Physical byte location within the `.elf` binary file on disk. |
| **Link-Time Virtual Address (VA)** | `0x00010000` | Linker Script | Virtual address assigned to instructions/data during static linking. |
| **Load Virtual Address (LVA)** | `p_vaddr` | ELF Loader | Virtual address where a `PT_LOAD` segment must be loaded. |
| **Process Virtual Address (VA)** | `0x00000000`–`0xFFFFFFFF` | Process Execution | 32-bit linear address generated by load/store/fetch instructions. |
| **User Virtual Address** | `0x00010000`–`0x7FFFFFFF` | User Space Process | Isolated virtual address range accessible by unprivileged code. |
| **Kernel Virtual Address** | `0x80000000`–`0xFFFFFFFF` | OS Kernel (Supervisor) | Higher-half virtual range reserved for kernel text, data, and MMIO. |
| **Virtual Page Number (VPN)** | `VPN[1]:10, VPN[0]:10` | Sv32 MMU | Indices used to traverse the two-level page table hierarchy. |
| **Physical Page Number (PPN)** | `PPN[21:0]` (22 bits) | Sv32 Page Table Walker | Physical frame number identifying a 4-KiB frame in physical memory. |
| **34-Bit Physical Address (PA)** | `PA[33:0]` | Memory Controller / Cache | Actual hardware physical address sent to cache and memory bus. |
| **MMIO Physical Address** | `0x80000000`–`0x8000FFFF` | SystemMMIO Bus | Hardware registers, telemetry counters, and precise trap controllers. |
| **Capability Effective Address** | `c.base + c.offset + imm` | CapabilityChecker | Bounded pointer address verified against spatial capability metadata (applies to `CL*`/`CS*`). |
| **Cache Set / Tag Address** | `[Tag:20][Set:6][Offset:6]` | L1 / L2 Cache Controllers | Cache index and tag bits used for fast hardware line lookups. |
| **Storage Block Address (LBA)** | Sector Index (512B/4KB) | Objective 4 Block Device | Secondary storage block address for file storage and paged-out swap. |

## 3. Dual-Layer Fault Separation

The system implements two completely separate, orthogonal protection mechanisms. They are never merged into a single generic fault:

```
Memory Reference (Effective VA)
          │
          ▼
1. CapabilityLite Check ──── (Bounds exceeded / Tag == 0 / Perm violation on CL*/CS*)
          │                                  │
          │                                  ▼
          │                   CAPABILITY FAULT (Precise Security Trap)
          │                   AN32-Bare-v1: TRAP_CAUSE = (accessType << 4) | reason
          │                   AN32-System-v1: scause = 24..29 (Custom RISC-V Range)
          ▼
2. Sv32 MMU Page Check ───── (PTE.V == 0 / PTE.U == 0 in user mode / PTE.W == 0 on store)
          │                                  │
          │                                  ▼
          │                   PAGE FAULT (OS Virtual Memory Exception)
          │                   AN32-System-v1: scause = 12 (Inst), 13 (Load), 15 (Store)
          ▼
3. Physical RAM / Cache Access
```

### Key Differences:
- **Capability Faults** represent **security violations** against bounded object authority. In Bare-v1, they redirect the PC to the handler address stored in `TRAP_VECTOR` (default `0x00000800`) with atomic writeback suppression.
- **Page Faults** represent **operating system virtual memory events** (e.g. demand paging, copy-on-write, page allocation). The OS handles them by allocating a physical frame, updating page tables, and restarting the instruction.
